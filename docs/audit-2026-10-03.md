## 0. Headline findings (read these first)

1. **app.liveadaptiv.com still serves `adaptiv-updated`, not `Adaptiv`.** None of the work in the `Adaptiv` repo is on that domain: the crisis gate, the per-endpoint API, the iPEC-term removal, and the access-code unlock. That repo deploys to **app.consciousgrowth.coach**.
2. **On app.consciousgrowth.coach every AI call and every access-code check gets a 403.** That domain is missing from `ALLOWED_ORIGINS`, and in production `*.vercel.app` previews are off too. The client swallows the 403 and shows canned fallback text. Because the crisis screen runs *inside* each endpoint, it **never runs** on that domain.
3. **The live app at app.liveadaptiv.com has no crisis screening at all.** It still uses iPEC terminology ("Energy Leadership Master Practitioner (ELI-MP)", Catabolic/Anabolic, "Level 1: The Victim"). Its access-code unlock calls `/api/verify-cipher`, and that route doesn't exist in that repo, so the unlock will fail.
4. **Kinetic Audit's `/api/capture-lead` has no origin check and no rate limit.** It sends an email from `results@send.liveadaptiv.com` to *any address in the request*, and the body text and link come from the caller. Anyone can use it as an open mail relay for phishing on your sending domain.
5. **Fixer/Rusher/Freezer, the 10-question diagnostic, MailerLite and Resend are not in the Adaptiv app.** They live in `The-Kinetic-Audit`. Adaptiv has no archetype engine.

## 3. Archetype engine (Fixer / Rusher / Freezer)

**Location:** `The-Kinetic-Audit/app/page.tsx` only. **Adaptiv has no archetype scoring.** The only Adaptiv-family mention is a prompt line in `adaptiv-updated/src/lib/adaptiv-mind.ts` ("the Rusher's speed, the Freezer's ice, the Fixer's chains"). That's prompt copy, not scoring.

**The flow as coded:** 16 items total, not 10. There are **10 pattern questions** followed by **6 load questions**, with progress saved to `localStorage['kineticState']`.

- **Pattern items (ids 1–10):** each has 4 options tagged `rusher | fixer | freezer | integrated`.
- **Load items (ids 11–16):** each is a frequency scale, Never=0 to Almost daily=4. Load score runs 0–24.

**Real scoring logic:**

```ts
// count option tags across the 10 pattern answers
types = { rusher, fixer, freezer, integrated }   // each 0..10
maxOverall = max(all four)

if (maxOverall > 0 && integrated < maxOverall) {
  tied = survival types equal to maxOverall
  tied.length > 1 → "Mixed Default: Rusher / Fixer"   (audio mixed.mp3)
  else            → "The Freezer" | "The Rusher" | "The Fixer"
} else if (integrated === maxOverall) {
  "A Regulated Baseline"   // a tie with integrated goes to Regulated
  + "emerging" lean = survival types tied at max
  + or "quiet" lean = highest survival type below max
}

// Tier comes from load only, never from archetype
loadScore <= 8   → "Friction"   → free CTA: sovereign.liveadaptiv.com
loadScore <= 16  → "Smoldering" → "Adaptiv App", billing.liveadaptiv.com/…/68001ac0…
else             → "Inferno"    → "Burnout Rescue Workbook", liveadaptiv.lemonsqueezy.com/…/aab07394… (raw LS domain, TODO in code)
```

The Inferno tier sets `crisis: true`. That only shows a "moment of pause" box with static 988 text. It isn't text-based crisis detection (the quiz has no free text), and it doesn't block the upsell.

## 4. Crisis-intercept logic

### Where it lives
- **Adaptiv:** `api/_lib/shared.ts`. `screenForCrisis()` runs `normalizeForScreening()` (lowercase, curly quotes to straight, an explicit contraction list such as `don't`/`dont` → `do not`, `wanna` → `want to`, then strips non-letters). After that it applies one alternation regex built from `CRISIS_PATTERNS`:
  - explicit: `kill (myself|my self)`, `killing myself`, `suicid(e|al)`, `take my (own )?life`, `end (my life|it all)`, `ending my life`
  - ideation: `want to die(?! on (that|this) hill)`, `wish (i was|i were|i am) dead`, `better off dead`, `do not want to (be here|live|wake up|exist)`, `no longer want to (be here|live)`, `nothing (left )?to live for`, `no reason to (live|go on)`, `cannot go on(?! (with|about|for|to|without))`, `cannot do this anymore`, `cannot keep going`
  - self-harm: `self harm`, `harm(ing)? myself`, `hurt(ing)? myself`, `cut(ting)? myself`, `overdose`
- A hit returns `CRISIS_MESSAGE` (988, text HOME to 741741, findahelpline.com). The client's `raiseCrisis()` then routes to the bare `Crisis` view, which has `tel:988`, `sms:741741` and findahelpline links.
- **adaptiv-updated (the live app.liveadaptiv.com):** **no crisis screen anywhere.** Its own `api/ai.ts` comment says so. It relies only on Gemini `BLOCK_MEDIUM_AND_ABOVE`.
- **Elsewhere:** `The-Alchemist-Field-Guide/lib/adaptiv-mind.js` has its own `containsCrisisLanguage`, used by `pattern-analysis`. It's a separate implementation and isn't shared with Adaptiv.

### Regex test (run during this audit against `shared.ts` as committed)
- Fires correctly on all CLAUDE.md must-fire phrases: "I do not want to be here anymore" / "don't" / "dont", "I can't go on", "I want to kill myself".
- Stays quiet correctly on all must-not-fire phrases: vendor, die on that hill, killing me, dead tired, kill for a coffee.
- **Misses** common indirect phrasings: "I want to disappear forever", "I wish I could sleep and never wake up", "everyone would be better without me".

### Is it wired into every user-facing flow? **No.** Gaps in the `Adaptiv` code:

1. **Burnout intercept bypasses it.** `checkDepletion()` in `Horizon` (`App.tsx` ~l.790) keyword-matches `tired`, `done`, `exhausted` and similar on the client, *before* any server call. A message like "I'm exhausted and I want to kill myself" shows the Vitality Scan offer instead of crisis resources. The scan path (VitalityScan → Preservation → Integration) sends no user text until the Decree at the very end. By then the level readout and seeded decree have rendered and the session has been saved. `done` is also a substring match.
2. **Fail-open.** The client treats any non-2xx (403, 429, 500 from a missing API key, timeout, offline) as `crisis: false` and shows fallback content. The screen sits behind `guard()`, so a missing `GEMINI_API_KEY` or a rate limit also disables crisis detection. There's no client-side screen.
3. **Integration renders before the crisis check.** When `isLocked` turns true, the seeded decree (with the user's stressor text), the Level X → Y readout, "Clinical Read", and on non-burnout paths the Monthly Access/$47/$495 upsells all render. Only then does `/api/manifesto` reply `crisis`. The session is written to localStorage first, and `FREE_CYCLE` is set to true.
4. **"Go back" from Crisis re-enters the flow.** `Crisis` `onBack={goBack}` pops to the previous view. From Integration that re-mounts the readout, upsells and seed decree, then regenerates and raises crisis again.
5. **Never screened:** Parts Work fields `sensation`, `protection` and `needed`. `resourceMemory`, `needed` and `sensation` go into the coaching-questions `somatic` field, which that endpoint doesn't screen. Laser answers "result" and "permission" are never sent anywhere. Integration `goal.when` isn't screened.
6. `pattern-insight` crisis hits are swallowed (see 2c).
